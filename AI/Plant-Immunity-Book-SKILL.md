# Plant Immunity Book — AI 协作技能指南

> **用途**：本文件是 AI 协作完成《植物免疫学》Book 的核心指令。
> 在执行任何与本项目相关的任务之前，请先完整阅读本文件。
> 本文件仅供 AI 和作者内部使用，不随 Book 发布。

## 一、项目概览

### 1.1 定位

一本系统梳理植物免疫学知识的**在线电子书**，技术栈为 Obsidian（日常写作）+ MkDocs Material（在线发布）+ GitHub Pages（托管）。

**核心目标**：
- 系统学习：从宏观模型到分子机制到实验验证，建立完整知识体系
- 逻辑训练：展示每个重要发现背后的科学推理过程
- 认知演变：呈现领域认知如何一步步被修正，而非只给最终结论
- 知识共享：方便作者复习，也方便研究生系统入门

**不涉及**：
- 作者个人课题设计或科研思路（公开仓库）
- 以组学技术为主线的内容（组学只是工具）
- 代码教程或生信流程

**读者**：研究生及以上，具有分子生物学基础。

### 1.2 技术架构

```
Obsidian Vault（日常编辑）
    ↓ Obsidian Git 插件（每 10 分钟自动同步）
GitHub 仓库（版本控制，公开）
    ↓ GitHub Actions（push 后自动构建）
MkDocs Material → GitHub Pages（在线 Book）
```

## 二、写作风格规范

### 2.1 对标

对标 **Alberts《分子生物学》** 和 **Buchanan《植物生物化学与分子生物学》**。

### 2.2 核心原则

| 原则 | 要求 |
|------|------|
| **专业学术** | 中文为主，术语精准，不口语化。术语首次出现附英文全称，如：模式触发免疫 (Pattern-Triggered Immunity, PTI) |
| **因果驱动** | 每个机制必须交代因果链，不跳步骤，从"为什么"出发 |
| **认知演变** | 展示"过去怎么认为 → 关键实验改变了什么 → 现在的共识 → 还有什么争议" |
| **实验驱动** | 重要结论必须标注支撑实验和文献出处 |
| **思路拆解** | 对重要突破分析：作者面对什么问题？逻辑链怎么搭？关键实验是什么？创新在哪？ |
| **未解问题** | 每章末尾列出当前争论和开放问题，体现学科活力 |

### 2.3 语言细则

- 基因名用**等宽斜体**：`*FLS2*`、`*ZAR1*`
- 蛋白名正体加粗：**FLS2**、**ZAR1**
- 英文术语首次出现后可直接使用中文简称
- 物种名用拉丁斜体：*Arabidopsis thaliana*、*Pseudomonas syringae*
- 避免过度比喻，保持学术严谨
- 参考文献格式：(Author *et al.*, Year, *Journal*)

### 2.4 写作风格样例

```
2019 年，柴继杰团队与周俭民团队合作解析了拟南芥 *ZAR1* 抗病小体的
冷冻电镜结构 (Wang et al., 2019, Science)，这是首个完整的植物 NLR
激活态结构。

ZAR1 的激活遵循以下步骤：
1. 效应子 AvrAC 修饰宿主激酶 PBL2，被 ZAR1 复合体中的假激酶 RKS1 感知
2. ADP→ATP 交换引发 ZAR1 构象转变
3. 五个 ZAR1 单体组装为轮状五聚体
4. N 端 CC 结构域形成漏斗状通道插入质膜
5. Ca²⁺ 内流，触发细胞程序性死亡

这一发现确立了 CNL 类 NLR 作为钙离子通道直接执行细胞死亡的机制，
而非此前假设的通过下游信号级联间接激活防御响应。

> **认知修正**：在 ZAR1 结构解析之前，领域普遍认为 NLR 激活后
> 通过中间信号分子传递防御信号。抗病小体的发现表明 NLR 本身即是
> 效应器 (executor)，这一概念转变对理解 ETI 机制具有深远影响。
```

## 三、排版与视觉设计规范

### 3.1 整体风格

经典学术教科书排版，深绿色为主色调，搭配中文衬线字体，营造专业、沉稳、可信赖的视觉感受。

### 3.2 字体方案

| 用途 | 字体 |
|------|------|
| 正文 | Noto Serif SC（中文衬线） |
| 标题/导航/标签 | Noto Sans SC（中文无衬线） |
| 基因名/代码 | Source Code Pro（等宽） |

### 3.3 色彩体系

| 用途 | 色值 | 说明 |
|------|------|------|
| 主色（标题、章节号） | `#1a472a` | 深绿，学术沉稳 |
| 强调色（链接、编号） | `#2d7a4f` | 中绿 |
| 正文 | `#2c2c2c` | 近黑 |
| 辅助文字 | `#5a5a5a` | 灰色，用于英文术语、图注 |
| 页面背景 | `#faf9f6` | 暖白，模拟纸张质感 |
| 认知修正框 | 背景 `#fdf6e3`，左边框 `#d4a017` | 金色系 |
| 实验/思路拆解框 | 背景 `#e8f5e9`，左边框 `#2d7a4f` | 绿色系 |
| 未解问题框 | 背景 `#f3e5f5`，左边框 `#7b1fa2` | 紫色系 |

### 3.4 章节头部设计

每章开头包含以下元素：

```
[面包屑导航] 首页 › 第二部分 分子机制 › 第四章
[部分标签]   第二部分 · 分子机制          ← 小字，大写字母间距，绿色
[大章节号]   04                           ← 超大字号，低透明度，右侧浮动
[章节标题]   NLR 与抗病小体               ← 大字，衬线，深绿
[副标题]     从细胞内受体到钙离子通道...    ← 一句话导读，灰色无衬线
─────────────────────────── 3px 绿色分割线
[本章目录]   左侧绿色竖线标注的编号目录
```

### 3.5 特殊排版元素

#### 认知修正框（金色）

用于展示领域认知的关键转折点。标题固定为"◆ 认知修正"，金色左边框。
内容模式：过去的认知 → 关键转折 → 新共识 → 影响。

#### 思路拆解框（绿色）

用于拆解里程碑论文的逻辑。标题固定为"⬡ 思路拆解"，绿色左边框。
内部结构固定为四段：
- **面对的问题**
- **关键思路**
- **关键证据链**（用 ① ② ③ 串联）
- **影响**

#### 未解问题列表（紫色）

每个问题前有紫色圆形问号标记，问题标题加粗，补充说明用普通字重。

#### 机制步骤（时间线样式）

- 左侧绿色竖线连接各步骤
- 每步有绿色圆形编号
- 步骤标题加粗，后接详细说明
- **不使用普通有序列表**，必须用时间线视觉样式

#### 表格

- 表头深绿色背景白色文字
- 无衬线字体
- 行底浅色分割线，hover 变色

#### 图片/模式图

- 灰色背景卡片包裹
- 图注使用"**图 X.Y 标题。**"格式，无衬线小字
- 文字围绕模式图展开解释

#### 推荐阅读（三级分类）

- 🔴 **必读**：奠基性工作，不读无法理解本章
- 🟡 **重要**：深入理解的关键文献
- 🟢 **拓展**：前沿进展或不同视角

每篇文献双栏布局：左侧为文献信息（作者加粗、标题斜体、期刊灰色小字），右侧为推荐理由（灰色小字，左侧竖线分隔）。每篇都必须有明确的推荐理由，让读者知道"为什么要读"以及"读完能获得什么"。

#### 章节底部导航

双栏：左侧"← 上一章 章节名"，右侧"下一章 章节名 →"，上方细分割线。

## 十二、发布与排错（新增）

### 12.1 部署链路必须固定为 MkDocs

`/.github/workflows/deploy.yml` 必须满足：

- 触发路径包含 `docs/**` 和 `mkdocs.yml`
- 构建命令是 `mkdocs build --strict`
- 上传目录是 `site/`

严禁误切到 Quarto 链路（如监听 `book/**`、输出 `book/_book`），否则 `docs` 更新不会上线。

### 12.2 章节文件格式规则（避免乱码/错版）

- 推荐每章使用**纯 HTML 结构**（与 `AI/ch04-sample.html` 同类名体系）
- 不要混用“复杂 HTML + markdown 嵌套缩进”，避免被渲染成 `<pre><code>` 代码块
- 发布前必须检查生成页中不存在章节标题被转义的现象

### 12.3 左右侧栏规范

- 左侧栏：章节导航（由 `mkdocs.yml` 的 `nav` 生成）
- 右侧栏：本章目录（若默认 TOC 为空，使用 `docs/assets/javascripts/chapter-toc.v2.js` 从 `.page-wrapper h2` 动态生成）
- 禁止在 CSS 中隐藏 `.md-sidebar--primary` 或 `.md-sidebar--secondary`

### 12.4 缓存与资源版本

当用户反馈“GitHub 已更新但网页不变”时：

1. 先确认 workflow 已运行并成功
2. 若仍旧样式未更新，采用资源版本化（例如 `book-chapter.v2.css`、`chapter-toc.v2.js`）
3. 在 `mkdocs.yml` 引用新文件名，强制客户端拉取新资源
4. 让用户用 `?v=<commit_sha>` + `Ctrl+F5` 强刷

### 12.5 每次发布前检查清单

1. 本地 `python -m mkdocs build` 成功
2. `site/.../chXX.../index.html` 中无 `<pre><code>` 误渲染
3. 页面存在 `.md-sidebar--primary` 和 `.md-sidebar--secondary`
4. 页面已加载最新 `book-chapter.v2.css` 和 `chapter-toc.v2.js`
5. 推送后确认 Actions 的 Deploy run 成功
